AI Workbench Ingestion

Privacy Policy

Effective 18 September 2026

Scope. AI Workbench Ingestion is a private application operated by its owner for personal use. It is not offered as a public or multi-user service.

1. Information the application accesses

The application uses Google OAuth to access Google Drive on behalf of a dedicated Google account. It may read and update:

  • file and folder names, identifiers, locations and other Drive metadata;
  • source documents stored within the configured AI Workbench source area;
  • Plaud transcript and summary packages written to that area; and
  • the ingestion manifest used to track source identity, revision and synchronisation status.

The Google Drive authorisation scope can technically permit access to files available to the dedicated Google account. The application is separately configured to reject operations outside its designated source-folder boundary.

2. How information is used

Information is processed only to:

  • capture authorised source records;
  • create or update source packages in Google Drive;
  • detect changed and unchanged records;
  • prevent duplicate ingestion; and
  • monitor the reliability and security of the ingestion process.

Google user data is not used for advertising, profiling, sale, or training a publicly available machine-learning model.

3. Storage and processing

Source packages and manifests are stored in the owner's Google Drive. OAuth credentials are stored in Google Secret Manager. Scheduled processing runs in Google Cloud Run and uses temporary credential files that are removed when an execution finishes.

Operational logs may contain technical identifiers, timestamps, execution status and error details. The application is not designed to place transcript contents or OAuth credentials in logs.

4. Disclosure

Information is not sold or disclosed to advertisers. It is transmitted only as necessary to operate the application through Google Drive, Google Cloud and Plaud services under the owner's accounts and instructions.

5. Retention and deletion

Source packages remain in Google Drive until the owner deletes them. Credential versions and operational logs are retained according to the owner's Google Cloud configuration and can be disabled or deleted by the owner.

6. Security

Controls include a dedicated Google identity, restricted Drive sharing, application-enforced folder checks, encrypted credential storage and least-privilege Google Cloud service accounts. No security control can eliminate every risk, but access is intentionally limited to the personal ingestion purpose.

7. Google API data

Use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy , including its Limited Use requirements.

8. Revoking access

The owner can revoke the application's Google access at any time through the security and third-party access settings of the relevant Google Account. Revocation prevents future Drive synchronisation until access is authorised again.

9. Changes to this policy

This policy may be updated if the application's data sources, processing, storage or access model changes. The effective date above identifies the current version.

10. Contact

Questions about this application or policy can be sent to sh710.ai@gmail.com.
